# 本地启动（v2.4 预览）

解压或下载项目到可写目录，不需要 Git、Docker 或数据库。

- macOS：双击根目录 `Start.command`。
- Windows x64：双击 `Start.cmd`（脚本已提供，尚待 Windows 真机验证）。
- Linux x64 / arm64：在项目目录运行 `sh start.sh`（尚待真机验证）。

启动器优先复用 Node.js 22 或以上。没有合适版本时，从 Node 官方下载固定的 v24.22.2，验证 SHA-256 后解压到项目的 `.launcher/runtime`。不修改系统 Node、全局 npm 或系统 PATH。首次需要联网下载依赖并构建，之后配置和代码没有变化时跳过重复准备。macOS 下载分为 arm64、x64，Windows 首批仅提供 x64。

准备成功后使用生产服务器，只监听 `127.0.0.1`；浏览器打开 `http://localhost:端口`。3000 被占用时选择其他空闲端口，不关闭其他程序。同一目录重复启动会打开已有实例；首次准备过程中再次启动会提示等待。保持启动窗口打开，在该窗口按 Ctrl+C 停止本实例。关闭浏览器不会停止服务器。

## 配置与数据

默认无需填写密钥即可体验例句、粤拼和简繁转换。启动器只在 `.env.local` 不存在时从模板创建，不覆盖已有文件，也不修改 `.data` 用量账本或上传任何密钥。需要真实功能时按 [README](../README.md) 编辑配置，再停止并重新启动。不需要配置全部服务；本版本未新增密钥填写向导。

已有云端历史使用 Supabase 时，浏览器地址端口改变可能需要重新登录；同时检查 Supabase 的本地重定向地址配置。

## 故障处理

- 网络或下载失败：检查网络后重新启动。运行时哈希不符时不会执行下载内容。
- 安装或构建失败：查看启动窗口提示，检查网络、可用磁盘和目录写权限。未完成的阶段不会写入成功标记。
- 提示已有启动器：查看之前的窗口。若异常断电／退出，确认旧进程已停止后，仅删除 `.launcher/running` 再重试，不要删除 `.data` 或 `.env.local`。
- 系统阻止脚本：保留系统安全保护，按系统针对该文件的提示处理。Windows 策略可能阻止 PowerShell 脚本，启动器不会修改执行策略；可使用 README 的手动运行方式。
- macOS 文件没有执行权限：在项目目录执行 `chmod +x Start.command start.sh`，然后重试。最终 ZIP 的权限保留与下载安全提示仍需在干净设备验证。
- FFprobe 无法执行：启动会停止，检查下载平台、文件权限和系统安全提示。不会悄悄跳过音频时长验证。

## 验证范围

这是源码启动器预览，尚非经过全部目标平台验证的 Release 安装包。已在当前 Mac 上验证已有 Node 时的依赖安装、生产构建、回环启动与同目录重复启动复用；无 Node 下载引导、干净 macOS arm64/x64、Windows x64 和 Linux 仍需独立设备记录。启动入口会在系统缺少 Node 或 npm 时选择私有下载引导。

首次准备与真实 API 需要联网，不代表完全离线。没有购买服务或自动升级套餐的流程。暂不提供自动更新、桌面安装壳和云部署。
