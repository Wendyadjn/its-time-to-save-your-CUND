# 服务与部署说明

## 服务选择

`AI_PROVIDER` 决定初始翻译／转写服务。页面选择保存在当前浏览器，作用于后续请求；不会自动在服务商之间重试。朗读固定使用 Ondoku。

| 服务 | 翻译模型 | 转写模型／朗读声线 |
| --- | --- | --- |
| Groq | `qwen/qwen3.8-27b` | `whisper-large-v3` |
| 硅基流动 | `XingChenAGI/Xing4.0-29B` | `FunAudioLLM/SenseVoiceSmall` |
| Ondoku | — | `zh-HK-HiuGaaiNeural` |

硅基流动转写只返回文字，不返回逐段时间和置信度，因此全文标为待校对、暂停自动翻译，不提供单句原音定位。Groq 的质量指标同样不能保证发现所有漏字或幻觉。

Ondoku 合成语速为 1；页面提供 x1、x1.25、x1.5、x2 播放倍速。调整倍速不重新生成音频。全文一次生成，单句与单字按需请求；页面缓存最近 100 条音频地址，刷新后清除，地址失效需重新生成。

## 额度信息的来源

| 面板信息 | 数据来源与含义 |
| --- | --- |
| Groq 速率额度 | 真实翻译／转写响应头，按模型记录每日请求和每分钟 Token 的限制、剩余量与窗口重置时间；不是付费余额 |
| Ondoku 剩余字数 | 用户在官方账户核对后手动录入的快照，只存在当前浏览器，不随新调用自动扣减，也不自动补满 |
| 硅基流动余额 | 国内站原 `/user/info` 接口于 2026-08-14 停用，需到官方控制台核对 |
| 本站今日用量 | 本服务器所有使用者的请求尝试次数和朗读输入字数，不包含官网或其他应用的消耗 |

Groq 数据注明采样时间；缺少重置时间或窗口到期后不把旧剩余量当作当前值，换密钥后隐藏旧账户数据。语音小时／每日秒数等未返回的指标保持未知，不用请求数推算。刷新面板只读取已有数据，不发起模型调用。

Ondoku 标准 TTS API 不提供剩余字数查询。未注册试用与注册免费账户的月额度不同，以账户页为准。手动快照到达所填更新日只提示重新核对，不自动恢复额度。音频未生成可能与字数不足有关，但不能据此确定余额为 0。

参考：[Groq 限速响应头](https://console.groq.com/docs/rate-limits)、[Ondoku 标准 API](https://ondoku3.com/en/developer/api/standard-tts.html)、[Ondoku 免费额度](https://ondoku3.com/en/about/)、[硅基流动接口公告](https://api-docs.siliconflow.cn/docs/release-notes/overview)。

## 本站限额与存储

在 `.env.local` 或部署平台设置全站每日上限，修改后重启。默认值：

```dotenv
DAILY_TRANSLATE_LIMIT=100
DAILY_TRANSCRIBE_LIMIT=20
DAILY_TTS_LIMIT=100
DAILY_TTS_CHARACTER_LIMIT=10000
```

前三项为请求尝试次数，最后一项为朗读输入字数；0 表示停用，非法值也按 0 处理。按香港时间每日重置。请求发出前预占，失败、取消或进程中断不退次数；切换服务不重置上限。这些限制不是金额预算，服务商仍可能对失败或取消计费。

用量账本位于 `.data/service-usage.json`，已被 Git 忽略。保存最近七个使用日、最近调用状态及取得的 Groq 额度快照；不保存学习文本、录音、原始错误或明文密钥。`SERVICE_DATA_DIR` 可指定可写的持久目录。文件损坏或不可写时阻止新请求，避免限额失效；不要通过删除目录重置用量。

**当前账本只适合单 Node.js 进程。** 多实例部署需共享数据库事务；无持久磁盘环境不能依赖本地文件保存跨重启限额。启用 Supabase 历史不会自动迁移用量账本。

## 接口概览

| 接口 | 用途 | 应用限制 |
| --- | --- | --- |
| `POST /api/translate` | JSON：`text`、`direction`、可选 `provider` | 输入 1–3000 字，10 次／分钟 |
| `POST /api/transcribe` | multipart：`file`、可选 `provider` | 五分钟、10 MB，6 次／分钟 |
| `POST /api/tts` | JSON：`text` | 输入 1–12000 字，20 次／分钟 |
| `GET /api/services` | 本站状态与额度快照 | 不调用模型 |
| `GET /api/history` | 历史列表或按 `id` 查询详情 | 需登录，仅当前账号 |
| `POST /api/history` | multipart：`record`、可选 `audio` | 需登录；原音仍受时长与大小限制 |
| `DELETE /api/history?id=…` | 删除记录及关联原音 | 需登录，仅当前账号 |

分钟级限流与每日上限均由本站用户共享。音频经过扩展名、MIME、容器签名及 FFprobe 时长校验；检测临时文件在结束后删除。翻译请求体最多 32 KB，朗读最多 64 KB。

服务端超时：翻译 30 秒、转写与朗读 60 秒。客户端翻译 35 秒、转写与翻译整条流程 100 秒、单次朗读 65 秒。停止本地等待不保证取消上游生成或费用。

## 生产部署与访问保护

1. 使用支持 Next.js 服务端路由的环境，安装依赖并执行 `npm run build`、`npm start`；静态导出不适用。
2. 在服务器设置需要的服务密钥；生产环境不会自动读取开发电脑的 `.env.local`。对外提供 HTTPS，允许浏览器录音。
3. 启用历史时完成 [Supabase 配置](supabase-setup.md)，设置正式站点和回调地址，保留记录 RLS 与私有音频桶。
4. 为翻译、转写和朗读设置站点登录或网关访问保护。现有 Supabase 登录只保护历史接口，Origin 校验不等于身份认证。
5. 为用量账本提供持久存储；多实例时先改为共享限额。GitHub 推送只同步源码，不会自动配置密钥或部署网站。

音频上传与数据库写入不是跨服务原子事务。失败时会尝试清理并提示；遇到网络中断应先刷新历史确认结果。相同账号、内容和所选原音完全一致时，保存请求不会新增重复记录；升级前已有重复记录不会自动删除。删除原音失败时保留记录以便重试；云端删除成功后无法在网页恢复。
